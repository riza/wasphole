**wasphole is an open-source MCP honeypot for the AI-agent era.**

It impersonates a real MCP server, exposes believable tools and resources, simulates a consistent Linux or Windows environment, plants canary credentials only where secrets naturally belong, records the full session, and alerts when an agent starts doing recon, escalation, or exfiltration.

Use it when you want to know whether an MCP-connected agent is behaving like a user, a scanner, or an attacker.

## Why this exists

MCP gives AI agents a structured way to discover tools, read resources, and interact with internal systems. That is useful, but it also creates a new recon surface:

- Agents can enumerate `tools/list` and `resources/list`.
- Prompt-injected agents can hunt for credentials, config, logs, and system files.
- Malicious agents can retry errors, escalate from read to write to execute, and exfiltrate data through downstream context.
- Traditional honeypots do not understand MCP semantics, tool calls, model-driven probing, or prompt-injection behavior.

wasphole is a deception layer for that surface.

## Prerequisites

- Go 1.25+
- An Anthropic API key or an OpenAI-compatible API key
- Optional: `jq` for reading session replay logs

## What it does

- **Looks like a real MCP server**: supports stdio and streamable HTTP transports through the standard MCP protocol.
- **Generates a unique identity**: server name, persona, and business tools are generated by an Anthropic or OpenAI-compatible model and cached to disk.
- **Simulates a coherent OS**: Linux and Windows modes return internally consistent hostnames, users, processes, logs, config, ports, registry/WMI data, and application resources.
- **Keeps responses stable**: AI-generated responses are cached by tool and params so repeated calls return the same answer across restarts.
- **Makes required fields discoverable**: mutation tools can be paired with lookup tools, such as `get_orders` revealing valid `order_id` and `order_type` values for `set_order_type`.
- **Plants canaries selectively**: fake credentials are inserted only into natural secret-bearing surfaces and attributed back to the originating session.
- **Detects behavior**: recon, retry loops, bulk reads, credential-path access, read/write/execute escalation, and canary fires become alerts.
- **Records sessions**: each session is written as JSONL for replay, investigation, and research.

## Quickstart

```bash
git clone https://github.com/riza/wasphole
cd wasphole

cp config.yaml.example config.yaml
export ANTHROPIC_API_KEY="sk-ant-..."

make build
./wasphole server -config config.yaml
```

By default the example config runs HTTP transport on port `8080` and writes session logs to `./sessions`.

For a fast local run:

```bash
make run
```

For tests:

```bash
make test
```

## Claude Desktop / stdio usage

Set `transport.type: stdio` in `config.yaml`, then add wasphole as an MCP server.

```json
{
  "mcpServers": {
    "wasphole": {
      "command": "/absolute/path/to/wasphole",
      "args": ["server", "-config", "/absolute/path/to/config.yaml"]
    }
  }
}
```

## HTTP usage

Set `transport.type: http` and choose a port:

```yaml
transport:
  type: http
  port: 8080
```

Then run:

```bash
./wasphole server -config config.yaml
```

wasphole starts a streamable HTTP MCP server on the configured port.

## Configuration

See [`config.yaml.example`](config.yaml.example) for the full annotated reference.

| Section | Purpose |
|---------|---------|
| `instance` | Simulated OS mode, industry context, deterministic seed |
| `ai` | Anthropic or OpenAI-compatible API settings, model, cache directory |
| `transport` | `stdio` or `http`, plus HTTP port |
| `alerts` | stdout, webhook, and SIEM alert sinks |
| `canary` | DNS base domain, HTTP callback, built-in canary listener |
| `session` | JSONL session log directory |

Minimal Linux example:

```yaml
instance:
  mode: linux
  industry: fintech
  seed: ""

ai:
  api_type: anthropic
  model: claude-sonnet-4-6
  cache_dir: ./cache

transport:
  type: http
  port: 8080

alerts:
  sinks:
    - type: stdout
      enabled: true

canary:
  domain: ""
  http_callback: ""
  listen_addr: ""

session:
  log_dir: ./sessions
```

## AI providers

wasphole supports two API wire formats:

- `anthropic`: uses `ANTHROPIC_API_KEY` when `ai.api_key` is empty.
- `openai`: uses `OPENAI_API_KEY` when `ai.api_key` is empty, and can point at OpenAI-compatible providers via `ai.base_url`.

Examples:

```yaml
ai:
  api_type: anthropic
  model: claude-sonnet-4-6
```

```yaml
ai:
  api_type: openai
  base_url: https://api.deepseek.com/v1
  model: deepseek-chat
```

## Simulated attack surface

wasphole combines deterministic OS simulation with AI-generated business context.

### Linux mode

Built-in tools include:

| Tool | What it simulates |
|------|-------------------|
| `execute_shell` | Shell command execution with realistic command output |
| `read_file` | Filesystem reads such as `/etc/passwd`, `/proc/*`, logs, config |
| `query_database` | AI-generated SQL query results consistent with the persona |
| `write_file` | Fake write success without touching the real filesystem |
| `list_processes` | Process listing for the simulated host |

Business tools also include discoverable workflows. For example, `get_orders` returns realistic order IDs and allowed order type values, while `set_order_type` requires `order_id` and `order_type` and points the caller back to `get_orders`.

Built-in resources include:

- `file:///etc/config.yaml`
- `file:///var/log/app.log`
- `file:///app/current/VERSION`

### Windows mode

Built-in tools include:

| Tool | What it simulates |
|------|-------------------|
| `run_command` | PowerShell/cmd command execution |
| `read_registry` | Registry reads such as Windows version and installed software |
| `query_wmi` | WMI-style system information |
| `write_file` | Fake write success without touching the real filesystem |
| `get_process_info` | Tasklist-style process output |

Built-in resources include:

- `file:///C:/config/app.config`
- `file:///C:/Logs/app.log`

## Detection logic

wasphole classifies behavior per MCP session.

| Level | Pattern | Trigger |
|-------|---------|---------|
| `INFO` | `connection` | Any new MCP session |
| `WARN` | `recon` | 3+ distinct system-path reads |
| `WARN` | `exfil` | Credential-path access or 5+ reads within 60 seconds |
| `WARN` | `retry` | 3+ consecutive errors on the same tool |
| `CRITICAL` | `escalation` | Read + write + execute behavior in one session |
| `CRITICAL` | `canary` | A canary token is fired |

Example stdout alerts:

```json
{"level":"INFO","ts":"2026-06-03T12:00:00Z","session_id":"abc12345","pattern":"connection","message":"MCP session connected"}
{"level":"WARN","ts":"2026-06-03T12:00:05Z","session_id":"abc12345","pattern":"recon","message":"recon pattern: 3 distinct system paths accessed","count":3}
{"level":"WARN","ts":"2026-06-03T12:00:08Z","session_id":"abc12345","pattern":"exfil","message":"exfiltration pattern: credential path accessed via read_file"}
{"level":"CRITICAL","ts":"2026-06-03T12:00:10Z","session_id":"abc12345","pattern":"canary","message":"canary token fired: 9fd21a2b7c4e"}
```

## Alert sinks

```yaml
alerts:
  sinks:
    - type: stdout
      enabled: true

    - type: webhook
      url: https://hooks.example.com/wasphole-alerts
      webhook_secret: "" # optional Base64 HMAC secret
      enabled: false

    - type: siem
      format: cef # "cef" or "json"
      path: /var/log/wasphole/siem.log # empty = stderr
      enabled: false
```

CEF example:

```text
CEF:0|wasphole|wasphole|1.0|WARN|recon pattern: 3 distinct system paths accessed|7|sessionId=abc12345 msg=recon pattern: 3 distinct system paths accessed pattern=recon cnt=3
```

## Canary tokens

wasphole does not decorate every response. Canary credentials are planted only in natural secret-bearing surfaces, such as `.env`, config files, credential paths, `/proc/self/environ`, or AI-generated business responses that explicitly contain the `{{CANARY_CRED}}` placeholder.

Token types:

- **Credential canary**: realistic prefixes such as `sk_live_`, `sk-proj-`, `pat_`, `api_`, `token_`, or `ghp_`.
- **Metadata URL canary**: generated for attribution when `canary.domain` is configured, but not blindly appended to ordinary command output.
- **DNS canary**: random subdomain under `canary.domain`, available for future/natural DNS-bearing surfaces.

Enable the built-in listener:

```yaml
canary:
  domain: canary.yourdomain.com
  listen_addr: ":9090"
  http_callback: https://hooks.example.com/canary
```

Placeholder domains such as `example.com`, `localhost`, and `canary.local` are intentionally ignored for URL/DNS canary generation.

## Session replay

Sessions are recorded as JSONL in `session.log_dir`.

```bash
ls sessions/
cat sessions/abc12345.jsonl | jq .
```

Each entry includes:

- `session_id`
- `type`: `request`, `response`, or `error`
- `method`
- `ts_ms`
- raw params, result, or error text

## Architecture

```text
MCP client / AI agent
        |
        | stdio or streamable HTTP
        v
  wasphole MCP server
        |
        +-- identity generator      -> cached generated persona + tools
        +-- OS simulator            -> Linux/Windows fake system state
        +-- response cache          -> stable AI-generated business responses
        +-- canary issuer/listener  -> token injection and attribution
        +-- session recorder        -> per-session JSONL
        +-- alert engine            -> stdout, webhook, SIEM
```

Important implementation choices:

- The generated identity is cached in `cache/identity.json`.
- Runtime AI responses are cached by tool and params.
- Simulated writes do not write to the real filesystem.
- `/etc/shadow`-style access returns permission errors instead of fake secrets.
- Canary token IDs do not embed the session ID; attribution is server-side.

## Operational notes

- Treat wasphole as internet-facing deception infrastructure. Do not run it with secrets in the config file if you can use environment variables.
- Use a stable `instance.seed` when you want a deployment to keep the same personality across cache rebuilds.
- Rotate or isolate `cache/` when you want a fresh generated identity.
- Pipe stdout alerts to `jq`, a log shipper, or your SIEM during testing.
- Put the canary listener behind a real domain if you expose natural URL/DNS-bearing lure data.

## Threat model

wasphole is designed to detect and profile:

- prompt-injected agents attempting unauthorized tool/resource access
- autonomous agents performing MCP recon
- agents reading system files, logs, configs, credentials, registry, WMI, or process state
- agents escalating from read-only discovery into write/execute behavior
- exfiltration of fake credentials or metadata URLs into downstream systems

It is not intended to:

- block attacks by itself
- replace MCP authorization, network controls, or sandboxing
- modify an attacker's environment
- expose real secrets
